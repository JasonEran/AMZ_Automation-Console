# 独立竞品情报第一版

入口：`/#intelligence`，沿用 AMZ Guard 登录。旧地址 `/intelligence` 自动跳转到此入口。

竞品情报与巡检各栏目共用工作台导航。首次进入时初始化一次，切换栏目保留页面、搜索、筛选及标签状态；仅在情报栏目可见且没有打开对话框时，每 15 秒刷新数据。界面通过 Shadow DOM 隔离样式与控件，后端数据和采集任务仍独立运行。

## 已实现范围

- 本平台独立的商品档案、产品线和规格对标，支持美国站、最多 30 个商品档案（包含停用档案，目前没有删除入口）。管理员维护，运营可查看。
- 通过对应店铺紫鸟的官方 WebDriver，只读采集一次性购买展示价和可购买状态。
- 保存每次结构化采样及字段级 DOM/页面文本证据，展示历史和数据缺失；认证、页面身份变化等情况下抑制不可信内容。
- 价格变动达到 5% 且至少 USD 1、可购买状态发生变化时，在已有基线之外再经两次独立可信采样确认，生成去重的变化卡。两次确认至少间隔一分钟。可信度按字段判断；报价缺失时，已取得双路证据的可购买状态仍可独立确认变化，缺失字段不更新基线。
- 关联本平台已落盘的自有 ASIN/VOC 报告，检查新鲜度；规格未确认、条件缺失和采集失败保持待核验。
- 手工维护库存、售价、单位成本、费用、最低库存/贡献利润要求和口径。记录来源时间、有效期及最近 500 条档案/经营参数审计；空值不替换成零。商品档案变更后，经营参数需要按新版本重新确认。
- 运营在本平台保存有效/无效结论和备注，保留最近 50 次复核修改。
- 单店“主销与对标”视图：固定区间的本店业务报告数量与竞品公开购买量提示分别展示；按关联商品分组，保留型号、打印页数、颜色和包装差异。
- 公开购买量提示从已校准的商品页主商品节点读取，并要求页面文本一致；仅用于已纳入样本的热度排序。缺失、过期与不同变体身份均不当成零销量，未推断竞品精确销量。

本模块不调用 CRM 接口、不依赖 CRM 登录、不采集 CRM 页面，也不生成 CRM 兼容导出或同步。新工作者不复用原巡检中会触发 CRM 的完整编排。内部标识、历史、参数和复核均由本平台持有。

## 使用步骤

1. 添加自有商品，选对应美国站店铺，填写产品线和型号/容量/颜色/包装数。
2. 添加直接竞品，选择该店铺下的自有对标商品；核实规格后勾选确认。也可只关注竞品，暂不关联自有商品。
3. 点击“立即采集”，或启用“每 12 小时监测”。首次可信采样建立基线，随后实际发生变化才会产生机会卡。
4. 在自有商品的“经营条件”维护当前参数；未填写仍可监测竞品，但不会显示承接条件满足。
5. 查看变化证据，填写人工复核结论和备注。价格下降属于竞争压力，不能自动解释成增长机会；本功能不执行调价、广告或采购操作。

新安装不填入虚构竞品、不导入界面验收示例，周期监测默认关闭。既有部署保留自己的真实档案和监测设置，代码更新不能覆盖运行数据。自有巡检中的 ASIN 不会自动成为竞品观察名单。

## 调度和数据

`amzguard-intelligence.timer` 每五分钟检查队列。每次工作者最多采集一个商品，持有与原巡检/商品上传相同的运行锁，完成后关闭该店铺会话。没有到期或手动请求的商品时不访问 Amazon。

自动监测以各商品上次采样时间为准（包括失败采样），间隔至少 12 小时；“立即采集”将请求时全部启用商品加入持久队列，不受这个间隔限制，已有请求不会重复建队列。任务繁忙或临近既有四个巡检窗口前 20 分钟至后 10 分钟时延后，并在页面显示。服务最长运行十分钟；异常中断后，页面按心跳过期提示，队列在后续调度恢复。第一版不承诺实时监控。

页面和自有报告关联使用 36 小时新鲜度；事件超过 72 小时转为历史记录，当前证据缺失、过期或与事件不符时不再作为当前机会。经营参数有效期由管理员填写（1～168 小时，表单初值 24 小时）。

- `out/state/intelligence/state.json`：商品、经营参数、基线、事件热索引、人工复核、队列、运行状态及有限审计，原子更新、独立进程锁、目录 0700 / 文件 0600。
- `out/intelligence/snapshots/<targetId>/`：不可变采样记录，按既有报告保留期清理，默认 365 天。历史分页每页 20 条。
- `out/intelligence/archive/`：超过热索引 2,000 条后的事件归档；第一版页面仅浏览热索引。归档供备份及后续历史检索扩展。
- `out/intelligence/selection/`：选品时的本店销量快照，记录店铺、明确日期区间、已核验子 ASIN、页面证据 SHA-256 和覆盖范围；不是滚动销量榜，不随商品页定时采样刷新。写入函数拒绝重复 ASIN，不自动汇总重复行；试点整理时排除无法解释的重复记录后，应保留部分覆盖标记。当前仅展示已保存的选品快照，没有通用文件导入或自动业务报告采集入口。

只有既有源码、示例配置与文档进入部署包。真实配置、登录凭据和 `out/` 不从本机覆盖到生产。情报 service 的 EnvironmentFile 只加载 `collector.env`，不加载 `channels.env`；紫鸟客户端另由自己的服务管理。

## 接口约定

读取沿用 Dashboard 登录，本地写入还需同源校验与 `X-Amzguard-Csrf`。接口由 `src/intelligence/http.js` 实现、`src/server.js` 挂载；下表写出完整路径。

| 方法与路径 | 用途与权限 |
|---|---|
| `GET /api/intelligence` | 汇总、档案、事件、经营参数、队列与运行状态；登录用户可读 |
| `GET /api/intelligence/targets/:id/history?page=1` | 指定档案采样历史，每页 20 条；登录用户可读 |
| `POST /api/intelligence/targets`、`PUT /api/intelligence/targets/:id` | 管理员建档或更新；更新携带当前 `version` |
| `PUT /api/intelligence/business/:id` | 管理员更新自有商品经营参数，携带参数 `version` |
| `POST /api/intelligence/run` | 管理员请求一轮采样，返回 `202`；不代表已访问 Amazon |
| `PUT /api/intelligence/settings` | 管理员保存 `autoCollect` 与当前状态 `revision` |
| `PUT /api/intelligence/events/:id/review` | 管理员或运营保存复核 `status`（`unreviewed` / `useful` / `dismissed`）、`note` 和当前复核 `version` |

版本冲突返回 `409`，刷新后再提交；没有 `/api/intelligence/overview`、`/api/intelligence/market` 或 `/api/intelligence/discovery` 路由。暂停周期监测不会取消已排队的手动请求。

## 验证与目前限制

离线覆盖：商品身份及版本、报价歧义、订阅价格区分、环境变化、两次采样、失败不更新基线、事件去重、经营参数过期与零库存、规格匹配、本地报告读取、共享锁、巡检窗口、CRM 外发隔离，以及登录、管理员/运营权限、同源和 CSRF。

截至 2026-09-11，已通过生产紫鸟完成单店试点的首轮只读验证，配置 3 个自有商品和 4 个竞品，并核对本店固定区间销量与商品页公开购买量提示。实际名单、销量和采样证据只保留在私有运行数据中，不随源码发布。更多竞品页面布局仍可能出现字段待核验，须依据真实页面证据扩充解析，而非把缺失值当成正常。

报价支持已校准的“一次性购买”选项及普通购买框结构；普通结构必须有唯一的完整报价、配送、购物车和卖家文本链并与主报价节点一致。不把订阅价、优惠券、Prime 条件价或配送费用合并成到手价。商品页当前报价可能来自其他卖家，不代表本店成交价。原始整页截图不属于第一版证据，页面提供字段前后值与文本佐证。下架/404 的观察不能自动推断真实断货。

未包含全量大盘、搜索排名、新品发现、销量归因、跟价模拟、外部通知与文件导入。已配置试点不代表完成七天连续业务观察，发布完成也不等于已验证增量销售效果。

## 部署和回退

按 `DEPLOY.md` 的本地门禁、服务器预检、停止 timer、备份、安装与验收执行。安装器包含新 service/timer 和最小权限检查。

暂停周期监测可在页面关闭开关。需停止整个新工作者时，先停止 `amzguard-intelligence.timer`，让已运行的只读任务自然结束；保留情报数据和历史。回滚代码按原部署流程进行，当前新模块不修改原九项检查的业务规则。
