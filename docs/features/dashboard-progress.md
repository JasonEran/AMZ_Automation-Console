# 巡检实时进度

巡检总览显示本轮执行进度条、当前检查与店铺、运行时长和每店进度圈。四个分类页的店铺检查小方框同步显示等待、采集、完成、采集异常或中断；上次业务结果在采集期间保留，并明确标注“上次”。执行完成不代表业务正常。

## 数据与刷新

- `src/checks/run.js` 为每轮任务创建独立 run ID、店铺 × 检查项队列，写入 `out/runtime/run-progress.json`，并每 5 秒更新心跳。每轮重置旧状态，避免上轮检查项或计数残留。
- 专用健康检查、通用检查和 ASIN 检查上报开始及完成事件。ASIN 单元记录实际计划数和已完成数，重试不重复计数；总体按店铺检查单元计算，商品进度作为单元内分数。
- `src/lib/run-progress.js` 统一转换状态，检查 PID 与任务锁是否匹配。进程消失或锁被新任务替代时，尚未完成的单元显示中断。心跳超过 30 秒显示延迟。
- 已登录用户可读取 `GET /api/progress`。接口不返回 PID、任务锁令牌、原始错误或内部 ASIN 去重列表。旧进度文件仍兼容。
- 页面每 2 秒读取进度，每 30 秒刷新报告；任务开始、单元完成及任务结束时加快报告刷新。并发响应按更新时间合并，避免旧响应回滚进度。
- 断线或心跳延迟时停止旋转并提示状态待确认；完成、失败、中断后均停止运行圈。支持手机布局与系统减少动态效果偏好。

## 验证

`npm test` 包含 `test/run-progress.test.js` 的队列、并发、ASIN 分母与重试、历史兼容、锁与中断、新轮重置、真实编排事件和页面状态断言。发布后用紫鸟只读任务验证实际进度文件、认证 API、报告结果和完成状态。
