# Dashboard 使用说明

## 启动与工作区

本地默认监听 `127.0.0.1:4173`：

```bash
npm run serve
```

生产部署方案由 systemd 守护，Node 仍只监听回环地址，Nginx 在 `https://amzcheck.pc51.com` 提供 HTTPS、登录限流与安全响应头；实际部署版本和健康状态另按运维验收核实。非回环或 `NODE_ENV=production` 时，缺少至少一个 Dashboard 用户、足够长度的 Session Secret 或独立 ingest token都会直接拒绝启动。看板按“每个店铺 × 每个检查项的最新有效报告”合并，单店补跑不会覆盖其他店铺结果；界面拆分为巡检总览、店铺风险、客户声音、商品状态、竞品情报、广告值守、上传中心、系统保障、用户管理和店铺配置十个工作区，巡检详情和历史等长列表独立分页。广告值守页可维护每店名称特征，范围和判定见[广告范围与判定](../reference/checks.md#广告范围与判定)；缺少规则时会在打开店铺浏览器前失败关闭。商品状态页展示动态活跃/非在售数量，但绝不自动修改商品；系统保障页显示 DOM 与页面文本双路证据完整率。紫鸟会话中心只展示登录/采集健康和建议动作，不读取密码、验证码或 Cookie。

管理员在“店铺配置”维护店铺绑定、独立展示名和启用状态，并调整页面刷新、分页与默认工作区。保存只更新私有 JSON，不触发 Amazon 采样或 CRM 写入；字段、保护和生效范围见[配置管理](../operations/operations.md#店铺与页面配置)。

生产部署不要使用旧 Windows 脚本；按 [部署手册](../operations/deployment.md) 的 Linux 单主机流程执行。

## 账户与行动分类

用户管理工作区支持管理员创建、停用、删除账户、调整角色和重置密码；每个用户也可修改自己的密码。改密或角色变更会使旧会话失效。

看板根据处理职责将结果分为四类：`正常`（无需处理）、`业务待处理`（运营）、`采集待修复`（技术）和`未完成`（排程）。原始 `OK/WARN/CRITICAL/ERROR`、状态码、双路证据与截图仍可在详情中核验；数据过期按采集待修复显示，不能继续保持绿色。
