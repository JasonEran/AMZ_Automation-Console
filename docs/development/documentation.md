# 文档规范

## 目录与命名

| 位置 | 职责 |
| --- | --- |
| 根目录 | README、CONTRIBUTING、SECURITY、CHANGELOG、DEPLOY 和 AGENTS 等固定入口 |
| `docs/development/` | 开发环境、提交、版本和文档规范 |
| `docs/operations/` | 部署、值守、故障与安全流程 |
| `docs/features/` | 面向使用者的功能说明 |
| `docs/integrations/` | 外部系统接入与数据交换 |
| `docs/reference/` | 规则、参数和状态参考 |
| `docs/archive/` | 按事件、发布、规划分类的历史材料 |

新增文件使用小写英文及连字符，如 `product-upload.md`。事件和发布记录使用 `YYYY-MM-DD-topic.md`。`docs/crm-openapi.json` 由运行时读取，保持原路径。

## 内容与表达

- 每篇一个一级标题；按主题使用二、三级标题，不跳级。
- 开头说明用途、适用对象或文档状态。使用明确动词，避免口语化标题与未经验证的结论。
- 区分当前能力、计划能力、测试结果和生产验证；“已部署”须有发布记录。
- 测试数量写在有日期的记录中，常规操作文档不固定数量。
- 配置示例只使用占位值。命令注明环境、前置条件和副作用。
- 优先相对链接；迁移时更新引用和索引，同一套规则不重复维护。
- 历史记录保留当时事实并标注时效，操作流程链接到现行手册。

## 校验

```bash
npm run docs:check
git diff --check
```

文档检查验证本地 Markdown 链接、标题锚点、唯一一级标题和标题层级。不访问外部链接，不校验生产状态。代码、参数和示例还需对照实现核实。
